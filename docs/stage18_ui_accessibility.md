# مرحلهٔ ۱۸ — تکمیل UI/UX و دسترس‌پذیری پایه

ادامهٔ همان سورس مرحلهٔ ۱۷؛ **۷۳ ابزار و ۹ دسته** حفظ شده‌اند. هیچ موتور محاسباتی، قرارداد ذخیره‌سازی، migration، dependency، فونت یا لوگویی در این مرحله عوض نشده است. فایل‌های اصلی تغییرات در `docs/validation/stage18/changed-files.txt` فهرست شده‌اند.

## تغییرات واقعی محصول

### خوانایی و تم

- برای هر ۹ دسته رنگ مستقل در **هر دو تم** نگه داشته می‌شود؛ حالت تاریک دیگر همهٔ آیکون‌ها را به رنگ اصلی مشترک تبدیل نمی‌کند.
- `CategoryColors` رنگ پیش‌زمینه را با luminance واقعی sRGB روی پس‌زمینهٔ composited تنظیم می‌کند؛ نسبت کنتراست رنگ آیکون دسته حداقل **4.5:1** است. نام و آیکون در کنار رنگ باقی می‌مانند؛ اطلاعات صرفاً رنگی نیست.
- تست نسبت برای متن روی surface، متن نتیجه روی primaryContainer، متن دکمهٔ primary، خطا و متن ثانویه، حداقل **4.5:1**؛ برای indicator فوکوس روی سطح/پس‌زمینهٔ دسته حداقل **3:1** است. این تست‌ها رنگ‌های مشخص فعال را پوشش می‌دهند، نه تمام پیکسل‌های تمام وضعیت‌های بومی.
- کنترل‌ها tap target پایهٔ ۴۸ logical pixel و تراکم استاندارد دارند. دکمه‌ها/ورودی‌ها indicator فوکوس مرئی دارند و کارت دسته با فوکوس کادر و با hover تغییر رنگ ظریف می‌گیرد.
- نمایش متن سیستم بدون clamp حفظ شده است؛ در تست‌ها تا **۲۰۰٪** بررسی شد. اندازه‌های بزرگ‌تر ممنوع نشده‌اند اما تضمین آزموده‌شده برای تمام مقادیر نامحدود نداریم.

### layout و RTL

- خانه و دسته‌ها: تعداد ستون‌ها به عرض **و text scale** وابسته است (۱ تا ۴ ستون). توضیحات طولانی فهرست ابزارها کوتاه نمایش داده می‌شوند؛ صفحهٔ کامل ابزار و اطلاعات واحدها حذف نشده است.
- صفحهٔ ماشین‌حساب: نتیجهٔ اصلی پیش از عمل‌های خروجی قرار می‌گیرد؛ علت کوتاهِ غیرفعال بودن PDF خواناست و tooltip/مستند مرحلهٔ ۱۷ دلیل کامل را نگه می‌دارد. فرم، مثال، توضیح، هشدار و تبدیل‌ها همان قبلی‌اند.
- واژه‌نامه از سربرگ ثابت + لیست مستقل به **یک CustomScrollView** تبدیل شد؛ متن بزرگ، پنجرهٔ کوتاه و صفحه‌کلید دیگر نباید باعث سرریز سربرگ شوند. جست‌وجو/فیلتر در دسکتاپ کنار هم و در عرض کم زیر هم‌اند. کنترلر query و انتخاب فیلتر هنگام resize حفظ می‌شوند.
- **صفحهٔ مستقل تاریخچه** اضافه شد (`/history`، دکمهٔ «نمایش تاریخچه» در خانه یا Ctrl+H). از همان repository/session واقعی استفاده می‌کند؛ جدیدترین ثبت اول، حداکثر ده مورد، timestamp محلی با برچسب تقویم میلادی و بازگشایی دقیق ورودی خام. بخش تاریخچهٔ خانه حذف نشده است.
- تنظیمات محدودیت عرض خوانا و فهرست قابل پیمایش، label حالت تم، تنظیم کاهش حرکت و راهنمای صفحه‌کلید دارد.
- نام انگلیسی واژه‌نامه و فرمول ریاضی LTR هستند؛ تاریخ/ساعت و خروجی‌های ترکیبی تاریخچه از isolate مناسب بهره می‌برند. ارقام فارسی/عربی ورودی و واحدهای قبلی همچنان پشتیبانی می‌شوند.

### ماوس، صفحه‌کلید و فوکوس

- گروه پیمایش با ReadingOrderTraversalPolicy در ریشه؛ برگه‌ها، دکمه‌ها و فیلدها از کنترل‌های استاندارد Flutter استفاده می‌کنند.
- Ctrl+F: تمرکز جست‌وجوی خانه/واژه‌نامه و نمایش کنترل با اسکرول. بدون کلیک اولیه نیز فعال است.
- Alt+I: اولین ورودی ماشین‌حساب و اسکرول به آن. FocusNodeها با فرم ساخته/آزاد می‌شوند و بین runnerها نشت نمی‌کنند.
- Ctrl+Enter: ثبت **همان ورودی/نتیجهٔ زنده و معتبر** در تاریخچه؛ ورودی نامعتبر و storageBusy ثبت نمی‌شوند. دادهٔ محاسبه‌شدهٔ قدیمی از frame قبل استفاده نمی‌شود.
- Ctrl+H: تاریخچه؛ Alt+Left: بازگشت. کلیدهای مسیر/ثبت auto-repeat ناخواسته ندارند.
- Tab/Shift+Tab، Enter روی کارت و دکمه، Arrow keys در dropdown و رفتار استاندارد Escape منو/دیالوگ باقی می‌مانند. میان‌برهای کپی/چسباندن یا انتخاب متن override نشده‌اند.
- cursor کارت/ابزار کلیک‌پذیر است؛ hover دسته و چرخ ماوس تاریخچه آزموده شدند. Windows از رفتار استاندارد scrollbar دسکتاپ Flutter استفاده می‌کند؛ wheel ماوس به عنوان touch drag مصنوعی اضافه نشده است.

### semantics و حرکت

- نام و تعداد ابزار دسته در یک label دارای نقش button و action واقعی؛ عنوان‌های بخش header هستند.
- ستارهٔ ابزار label شامل نام همان ابزار، نقش button، enabled و حالت toggled دارد؛ آیکون تزئینی یا tooltip باعث دو بار خواندن همان دکمه نمی‌شود.
- فیلدها نام، واحد/درصد، کمک و خطای استاندارد دارند. متن ریاضی label قابل فهم برای مراجعه به شرح محاسبه دارد و متن خام LaTeX همچنان قابل بازکردن/انتخاب است.
- live region نتیجه به خروجی اصلی کوتاه محدود شد، نه خواندن دوبارهٔ تمام کارت/هشدارها با هر تغییر. نتیجهٔ نامعتبر با cross-fade قدیمی نمایش داده نمی‌شود.
- fade مسیر ۱۸۰ms و تغییر رنگ/کادر ۱۴۰ms است؛ هیچ انیمیشن دائمی یا چشمک‌زن اضافه نشده است. درخواست کاهش حرکت OS همیشه مقدم است؛ switch داخلی نیز می‌تواند حرکت را خاموش کند. تم و کاهش حرکت همچنان تنظیمات **همین اجرای برنامه** هستند، نه دادهٔ دائمی جدید.

## پنجرهٔ Windows و DPI

کد runner موجود با `WS_OVERLAPPEDWINDOW` از قبل resizable/maximizable بوده است؛ این ویژگی حفظ شد، نه اینکه به‌اشتباه قبلاً ثابت فرض شود. پردازش `WM_SIZE` و `WM_DPICHANGED` و manifest **PerMonitorV2** موجود حفظ شده‌اند.

- نام پنجره به «جعبه‌ابزار مدیریت» تغییر کرد؛ literal به صورت Unicode escape در سورس C++ است تا به code page کامپایلر وابسته نباشد.
- `WM_GETMINMAXINFO` حداقل اندازهٔ **بیرونی** 360×360 logical pixel را با DPI مانیتور فعلی محاسبه می‌کند؛ اگر DPI نامعتبر/صفر باشد ۹۶ مبناست. اندازهٔ client کمی کوچک‌تر از قاب است؛ layout تا 320×568 و resize زنده تا 360×360 client در تست شبیه‌سازی شد.
- هیچ window manager dependency یا API جدید الزام‌آور برای Win11 اضافه نشده است. Android minSdk=26 و تنظیمات بومی قبلی تغییر نکردند.
- **کامپایل/اجرای بومی Windows، drag/maximize واقعی و انتقال بین مانیتورها در این محیط انجام نشدند.** نتیجهٔ widget-test با DPR شبیه‌سازی‌شده جایگزین این موارد نیست.

تعامل‌ها شامل فوکوس اولیه بدون ماوس، رفت/برگشت Tab، Alt+I، ثبت فقط نتیجهٔ معتبر، hover و Enter دسته، حفظ query/filter با تغییر عرض و viewInsets صفحه‌کلید، کاهش حرکت، مسیر واقعی ذخیره→تاریخچه→بازگشایی خام→بازگشت، چرخ ماوس، `androidTapTargetGuideline` و `labeledTapTargetGuideline` روی خانه هستند. این دو guideline برای کل همهٔ صفحات ادعا نمی‌شوند.

### محدودیت حافظهٔ اجرای تست و روش گزارش

محیط ۲GB است. بعضی تلاش‌های اولیه با رشد heap کامپایلر یا هم‌زمانی کامپایل فایل دوم و رندر فرم‌های متعدد قطع شدند؛ آن‌ها قبولی محسوب نشده‌اند. رندرها به PNG با pixelRatio=1 محدود، تست‌ها به فرایندهای مستقل تقسیم و heap ابزار کامپایل در **SDK موقت کش** محدود و GC آن پرتکرارتر شد (`--old_gen_heap_size=1024 --old_gen_growth_space_ratio=5 --old_gen_growth_rate=32`). این تنظیم ابزار توسعه است و در محصول/سورس ارسالی SDK دست‌کاری‌شده‌ای وجود ندارد.

تمام ۸۵ فایل در نهایت پوشش داده شدند. یک دستهٔ سنگین quality/inventory که در اجرای دوفایلی قطع شد، با همان assertions در دو اجرای تک‌فایلی مجدداً موفق/skip شد. `shards/summary.json` این retry، لاگ اولیهٔ قطع‌شده و هر دو لاگ نهایی را صریحاً پیوند می‌دهد؛ هیچ تست ناقص به عنوان قبولی شمرده نشده است. روی میزبان عادی با حافظهٔ کافی `flutter test` قابل استفاده است؛ برای میزبان کوچک `--batch-size 1` و TMPDIR روی دیسک توصیه می‌شود.

```sh
flutter pub get
flutter analyze
flutter test
# اجرای کامل در فرایندهای جدا، بدون حذف تست:
python tool/run_test_shards.py --flutter /path/to/flutter --batch-size 1 --output docs/validation/stage18/shards
# بررسی متمرکز:
flutter test test/accessibility --concurrency=1
# فرمت:
dart format --output=none --set-exit-if-changed lib test tool
```

لاگ‌ها: `docs/validation/stage18/`؛ تصاویر و چک‌لیست: [`visual/stage18/README.md`](visual/stage18/README.md).

## موارد باقیمانده پیش از انتشار

- build جدید APK و EXE، اجرا روی Android API26+ و Windows10/11، جابه‌جایی واقعی DPI، صفحه‌کلید نرم/لمسی/ماوس بومی.
- بررسی انسانی TalkBack و Narrator: ترتیب گفتار، اعلام error/result، focus و activation؛ semantics و guideline خودکار جای این آزمون را نمی‌گیرند.
- matrix screenshot بومی شامل اندازه‌های متن ۲۰۰٪، focus، error/empty، منوهای dropdown و high-contrast سیستم طبق چک‌لیست بصری. high-contrast سفارشی بومی یا تأیید جامع WCAG ادعا نمی‌شود.
- PDF همچنان طبق آزمون شکست‌خوردهٔ مرحلهٔ ۱۷ غیرفعال است؛ این مرحله آن را بی‌آزمایش فعال نکرده است. اشتراک بومی همچنان به آزمون دستگاه نیاز دارد.
- push/commit/publication و signing انجام نشده است؛ بستهٔ تحویل سورس کامل است و کلید/توکن ندارد.
