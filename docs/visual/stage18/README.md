# بازبینی بصری مرحلهٔ ۱۸ و screenshotهای موردنیاز

## تصاویر ثبت‌شدهٔ همین سورس

۲۴ تصویر در این پوشه: ۶ صفحه × دو تم × دو viewport. این‌ها **رندر widget-test Flutter با Vazirmatn محلی** هستند، نه screenshot از APK، EXE، TalkBack یا Narrator. شاخهٔ تم Android برای phone و Windows برای desktop انتخاب شده است؛ قاب بومی پنجره، فونت‌سازی GPU دستگاه و صفحه‌کلید واقعی سیستم در تصویر نیستند.

- `*-phone-dpr3.0.png`: viewport منطقی 390×844، DPR شبیه‌سازی‌شدهٔ 3، تم Android.
- `*-desktop-dpr1.5.png`: viewport منطقی 1280×900، DPR شبیه‌سازی‌شدهٔ 1.5، تم Windows.
- همهٔ خروجی‌های PNG برای محدودکردن حافظه با `capturePixelRatio=1` در اندازهٔ منطقی ذخیره شده‌اند؛ نام DPR به MediaQuery/نمای شبیه‌سازی‌شده اشاره دارد، نه رزولوشن فیزیکی فایل PNG. جزئیات در `capture-manifest.json` است.
- اندازهٔ متن این تصاویر ۱۰۰٪ است. تست‌های جداگانه متن ۱۵۰٪ و ۲۰۰٪ و تغییر اندازهٔ زنده را بررسی می‌کنند؛ به معنی موجود بودن تمام screenshotهای متن بزرگ نیست.
- دادهٔ تاریخچه فقط fixture آزمایش است: ۱۰ محاسبهٔ واقعی OEE با ساعت ثابت محلی 2026/10/16 12:30. هیچ دادهٔ ساختگی به محصول اضافه نشده است.
- تصاویر فعلی برای بازبینی‌اند، **golden baseline تأییدشدهٔ پلتفرم بومی نیستند** و آزمون تطبیق خودکار پیکسل‌به‌پیکسل ادعا نمی‌شود.

| پیشوند فایل | چه چیزی باید دیده/بررسی شود |
|---|---|
| `home-*` | راست‌به‌چپ بودن عنوان/جست‌وجو، کارت خوش‌آمد، نام/آیکون/رنگ مستقل دسته‌ها؛ نبود تکیهٔ صرف به رنگ |
| `category-*` | نام دسته، شمارندهٔ واقعی ابزارها، تمایز رنگ/آیکون، عنوان فارسی/مخفف لاتین و ستارهٔ مجزا |
| `calculator-*` | اولویت نتیجهٔ اصلی، درصد و کلمات لاتین، کپی/اشتراک، دلیل کوتاه غیرفعال بودن PDF و خوانایی جزئیات |
| `history-*` | آخرین ثبت در بالا، ۱۰ مورد، عدد نتیجه/درصد، ترتیب تاریخ و ساعت میلادی، ستاره و پیوند بازگشایی |
| `glossary-*` | جست‌وجو و فیلتر کنار هم در عرض بزرگ و زیر هم در تلفن، عنوان فارسی، نام انگلیسی LTR، پیوندها |
| `settings-*` | برچسب حالت تم، کاهش حرکت، راهنمای میان‌برها، متن خوانا و امکان پیمایش |

بازبینی انسانی چند تصویر نماینده شامل خانهٔ تاریک تلفن، واژه‌نامهٔ روشن دسکتاپ، محاسبه‌گر روشن تلفن و تاریخچهٔ تاریک تلفن انجام شد. این نمونه‌برداری جایگزین بررسی تک‌تک حالت‌های بومی زیر نیست.

## تولید مجدد تصاویر

Flutter 3.47.7 stable، dependencyهای lockfile و فونت‌های بسته را استفاده کنید. چهار اجرا جدا هستند تا مصرف حافظه محدود بماند:

```sh
flutter pub get
flutter test test/accessibility/visual_capture_test.dart --concurrency=1 --no-track-widget-creation --dart-define=CAPTURE_STAGE18_VISUALS=true --dart-define=STAGE18_CAPTURE_DEVICE=phone --dart-define=STAGE18_CAPTURE_DARK=false
flutter test test/accessibility/visual_capture_test.dart --concurrency=1 --no-track-widget-creation --dart-define=CAPTURE_STAGE18_VISUALS=true --dart-define=STAGE18_CAPTURE_DEVICE=phone --dart-define=STAGE18_CAPTURE_DARK=true
flutter test test/accessibility/visual_capture_test.dart --concurrency=1 --no-track-widget-creation --dart-define=CAPTURE_STAGE18_VISUALS=true --dart-define=STAGE18_CAPTURE_DEVICE=desktop --dart-define=STAGE18_CAPTURE_DARK=false
flutter test test/accessibility/visual_capture_test.dart --concurrency=1 --no-track-widget-creation --dart-define=CAPTURE_STAGE18_VISUALS=true --dart-define=STAGE18_CAPTURE_DEVICE=desktop --dart-define=STAGE18_CAPTURE_DARK=true
```

چهار manifest جزئی هر کدام شش تصویر را توصیف می‌کنند؛ manifest تجمیعی همراه تحویل همین ۲۴ مورد است. هر آزمون پس از ثبت تصویر، نبود استثنای layout را بررسی می‌کند. انتخاب دستگاه با مقدار دیگری به جای `phone`/`desktop` پشتیبانی نمی‌شود.

## چک‌لیست screenshotهای بومی لازم پیش از انتشار — هنوز انجام نشده

هر مورد زیر با ذکر نسخهٔ OS، نسخهٔ برنامه، اندازهٔ فیزیکی/منطقی، DPI، text scale، تم، روش ورودی و نتیجهٔ بازبینی ثبت شود. فایل‌های مرحله‌های قبلی baseline تاریخی‌اند و نباید بی‌بررسی جایگزین شوند.

### مجموعهٔ پایه برای هر شش صفحه

- Android API 26 و یک نسخهٔ جدیدتر؛ اندازه‌های تقریبی 320×568 و 390×844 منطقی؛ روشن و تاریک؛ متن ۱۰۰٪ و ۲۰۰٪.
- Windows 10 و 11؛ پنجرهٔ 1280×900 و پنجرهٔ باریک حدود 360×480؛ تم روشن/تاریک؛ Scale سیستم 100، 125، 150 و 200٪ و Text Size بزرگ.
- روی Windows: تصویر قبل/بعد از drag لبه، maximize/restore و انتقال بین مانیتورهای DPI متفاوت. پنجره نباید قفل اندازه، خارج از ناحیهٔ کار یا دارای محتوای برش‌خورده شود. حداقل اندازهٔ بیرونی 360×360 logical است؛ قاب سیستم از فضای client کم می‌کند.

### حالت‌های تکمیلی ضروری

1. **خانه:** ۹ دسته و رنگ متمایز؛ علاقه‌مندی خالی/پر؛ جست‌وجوی دقیق/تقریبی/بدون نتیجه؛ title کوتاه‌شده در پنجرهٔ باریک، با نام کامل در semantics.
2. **دسته:** تولید، مالی، کیفیت و یک دستهٔ با نام بلند؛ فوکوس مرئی روی کارت/ستاره؛ hover و کلیک ماوس بدون فعال‌کردن ناخواستهٔ ستاره هنگام بازکردن ابزار.
3. **محاسبه‌گر:** OEE، NPV با سری ورودی، ابزار تبدیل واحد با گزینهٔ بلند، یک خطای ورودی، نتیجهٔ معتبر/نامعتبر؛ متن ۲۰۰٪؛ صفحه‌کلید نرم باز؛ ورودی و unit قابل دسترسی با اسکرول؛ فرمول عریض با اسکرول افقی LTR؛ نتیجه نباید با انیمیشن قدیمی باقی بماند.
4. **تاریخچه:** صفر، یک و ده ثبت؛ بعد از یازدهم تعداد ده بماند؛ بازگشایی همان متن خام؛ ساعت/تاریخ کنار عدد فارسی/لاتین جدا و خوانا؛ تغییر ستاره بدون navigation.
5. **واژه‌نامه:** جست‌وجوی فارسی/انگلیسی، فیلتر، نتیجهٔ خالی، بازکردن توضیح کامل و پیوند؛ تغییر عرض در حین جست‌وجو بدون پاک‌شدن query/filter؛ پنجرهٔ کوتاه/صفحه‌کلید باز بدون overflow سربرگ.
6. **تنظیمات:** سه حالت تم؛ switch کاهش حرکت؛ اندازهٔ متن سیستم؛ حالت کاهش حرکت OS روشن و تنظیم داخلی خاموش (OS همچنان مقدم است).
7. **ماوس/صفحه‌کلید:** screenshot فوکوس کارت، دکمه و ورودی؛ Tab و Shift+Tab بدون دام؛ Enter/Space برای فعال‌سازی؛ Ctrl+F بلافاصله پس از ورود به صفحه؛ Alt+I و Ctrl+Enter؛ Ctrl+H و Alt+Left؛ Escape فقط برای منو/دیالوگ؛ Ctrl+C/V استاندارد باقی بماند؛ چرخ ماوس و scrollbar قابل استفاده باشند.
8. **متن ترکیبی:** واحدهای `°C/°F`، `m/s`، درصد منفی، `NPV/OEE/Cp`، پرانتز، تاریخ/ساعت، شماره‌های فارسی و لاتین؛ ترتیب بصری و معنی واحد/عدد با هم بازبینی شود، نه فقط وجود glyphها.
9. **TalkBack/Narrator:** گزارش متنی/ویدیویی علاوه بر screenshot؛ نام، نقش، حالت toggled/disabled، ترتیب خواندن RTL، تشخیص عنوان‌ها، نتیجه و خطا و فعال‌کردن همهٔ کنترل‌ها. screenshot به تنهایی دسترس‌پذیری صفحه‌خوان را ثابت نمی‌کند.

### معیار رد

RenderFlex overflow، مخفی ماندن کنترل ضروری، text clipping بدون راه دسترسی به متن، focus نامرئی/گم‌شده، جابه‌جایی غلط علامت/واحد، حذف ورودی با resize، اطلاعات صرفاً رنگی یا خطای صفحه‌خوان مانع تأیید است. متن دکمهٔ واقعاً غیرفعال از الزام کنتراست متن فعال مستثناست، اما علت غیرفعال بودن باید خوانا باشد. آزمون‌های فعلی گواهی جامع WCAG نیستند.
