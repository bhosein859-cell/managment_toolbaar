# مرحلهٔ ۸ از ۲۰ — خانه، دسته‌بندی و جستجوی آفلاین

## دامنه و مسیر استفاده

این مرحله ادامهٔ همان کدبیس است، نه بازنویسی پروژه. از ورود به برنامه به خانه می‌رسید؛ تنظیمات، آزمایش فارسی و فرم آزمایشی همچنان در نوار بالای خانه در دسترس‌اند. برند، فونت محلی، RTL، سه حالت تم و محاسبه‌های مستقل قبلی حفظ شده‌اند.

خانه شامل جستجو، کارت‌های هشت دسته، علاقه‌مندی، آخرین محاسبات و ابزارهای آماده است. «همهٔ دسته‌ها» نمای کلی را باز می‌کند؛ هر کارت به فهرست ابزارهای دسته و شمارندهٔ واقعی آن می‌رود.

| دسته | ابزار قابل استفاده | تعداد |
|---|---|---:|
| تولید | OEE | ۱ |
| مالی | NPV | ۱ |
| کیفیت | Cp | ۱ |
| انبار | — | ۰ |
| پروژه | — | ۰ |
| منابع انسانی | — | ۰ |
| تصمیم‌گیری | — | ۰ |
| اقتصاد مهندسی | — | ۰ |

دستهٔ خالی پیام روشن دارد، نه لینک به ماشین‌حساب پیاده‌سازی‌نشده. فرم تشخیصی قدیمی عضو کاتالوگ اصلی نیست. شمارنده‌ها و جستجو از همان registry مشترک ساخته می‌شوند.

### علاقه‌مندی و آخرین محاسبات: فعلاً حافظهٔ همین اجرا

- ستارهٔ هر ابزار در خانه، دسته و صفحهٔ محاسبه همگام است و زدن ستاره ابزار را باز نمی‌کند.
- در صفحهٔ محاسبه دکمهٔ «ثبت در آخرین محاسبات» فقط برای نتیجهٔ معتبر فعال است. کلیک ثبت، ورودی خام immutable و نتیجه را همراه زمان و شمارهٔ ترتیبی نگه می‌دارد.
- بازکردن ابزار، مقدارهای پیش‌فرض و تایپ هر کلید خودکار ثبت نمی‌شوند؛ بنابراین سابقه با ورودی‌های میانی پر نمی‌شود.
- ده ثبت آخر، جدیدترین اول نمایش داده می‌شوند. هر کلیک ثبت یک رخداد است و ثبت تکراری عمداً حذف نمی‌شود.
- کلیک روی رکورد، همان ابزار را با همان ورودی‌ها باز می‌کند؛ نتیجه با موتور دوباره محاسبه می‌شود. خطای بعدی فرم، snapshot قبلی را خراب نمی‌کند.
- **با بستن برنامه یا ایجاد نمونهٔ تازهٔ اپ، این داده‌ها پاک می‌شوند.** SQLite، repository ماندگار، فایل تاریخچه، migration و ماندگاری تنظیمات در این مرحله اضافه نشده‌اند. notice داخل خانه هم این موضوع را توضیح می‌دهد. اتصال دائمی در مرحلهٔ پایگاه داده باقی است.

## قرارداد جستجو

همهٔ پردازش‌ها محلی‌اند؛ هیچ درخواست شبکه، سرویس جستجو، مدل زبانی، ارزیابی رشتهٔ فرمول یا بستهٔ جدیدی استفاده نمی‌شود.

### نرمال‌سازی فقط برای نمایه/پرس‌وجو

`SearchText` ارقام فارسی/عربی را لاتین، حروف انگلیسی را lowercase، ي/ى را ی، ك را ک و گونه‌های الف را ا می‌کند. اعراب، کشیده و نشان‌های جهت متن حذف می‌شوند. نیم‌فاصله/ZWJ به فاصله، جداکننده‌ها و فاصله‌های تکراری به شکل یکنواخت تبدیل می‌شوند. مقایسهٔ compact فاصله‌ها را هم نادیده می‌گیرد.

در نتیجه «بهره‌وری تجهیزات»، «بهره وری تجهیزات» و «بهرهوری تجهیزات» یک ابزار را پیدا می‌کنند. «اثربخشي كلي تجهيزات»، «ارزش‌خالص‌فعلی»، `Net present VALUE` و رقم‌های `123`/`۱۲۳`/`١٢٣` نیز در تست‌ها بررسی شده‌اند. **برچسب‌های اصلی و متن تایپ‌شده بازنویسی نمی‌شوند.** این normalizer برای متادیتای فارسی/انگلیسی این برنامه است، نه یک موتور جامع تطبیق همهٔ زبان‌ها.

### نمایه، رتبه‌بندی و fuzzy

- نمایه هنگام ساخت سرویس جستجو از کاتالوگ ساخته و بین تغییرهای متن دوباره استفاده می‌شود.
- نام فارسی/انگلیسی، شناسه، aliases و description جستجو می‌شوند؛ نام فارسی/انگلیسی دسته هم نمایه دارد.
- ترتیب امتیاز: برابری نرمال/compact، زیررشته، وجود همهٔ کلمه‌ها در فیلدهای مختلف، سپس تطبیق تقریبی. نام/مترادف وزن بیشتری از توضیح/دسته دارند. امتیاز برابر با شناسهٔ ابزار مرتب می‌شود.
- fuzzy از **optimal-string-alignment Damerau-Levenshtein محدود** با درج/حذف/جایگزینی و جابه‌جایی دو حرف مجاور استفاده می‌کند؛ جستجوی معنایی یا پیشنهاد فرمول دیگر نیست.
- کلمهٔ ۳–۵ حرفی حداکثر یک ویرایش؛ ۶–۶۴ حرفی حداکثر دو ویرایش. برای کلمهٔ کمتر از ۳ یا بیش از ۶۴ حرف fuzzy انجام نمی‌شود؛ تطبیق عادی همچنان ممکن است.
- تمام کلمه‌های پرس‌وجو باید match شوند. حد پیش‌فرض ۲۰ نتیجه، طول خام حداکثر ۲۵۶ کاراکتر و حداکثر ۱۶ کلمه است. ورودی بلندتر/خالی و limit نامعتبر نتیجهٔ خالی می‌دهند.
- نتیجهٔ تقریبی با «تطبیق تقریبی» مشخص است؛ `nvp` → NPV، `اثربخشب` → OEE، `capabilty` → Cp نمونه‌های تست‌شده‌اند. fuzzy ممکن است false positive داشته باشد؛ ابزار جدیدی ایجاد نمی‌کند.

## معماری و فایل‌ها

- `core/utils/search_text.dart`: نرمال‌سازی مستقل از UI.
- `features/home/domain/tool_catalog.dart`: کاتالوگ immutable، کنترل شناسهٔ تکراری/دستهٔ ناشناخته و فهرست‌های دستهٔ cache‌شده.
- `features/home/domain/catalog_search.dart`: نمایه، رتبه‌بندی و فاصلهٔ bounded؛ Pure Dart.
- `app/catalog/app_catalog.dart`: ترکیب هشت دسته و فقط سه تعریف اجرایی مرحلهٔ ۷. در `prototype_calculators.dart` فقط aliases اضافه شده‌اند؛ فرمول‌ها و موتور‌ها عوض نشده‌اند.
- `features/home/presentation/controllers/tool_session_controller.dart`: state یک اجرای اپ با ChangeNotifier؛ مالک آن `app.dart` است و dispose می‌شود. ساعت برای تست قابل تزریق است.
- `features/history/domain/recent_calculation.dart`: snapshot immutable.
- `app/state/tool_session_scope.dart`: اتصال state به مسیرها، بدون state-management package جدید.
- `app/routing/calculator_request.dart` و router: شناسه + ورودی اختیاری typed؛ آرگومان اشتباه یا شناسهٔ ناشناخته به صفحهٔ امن not-found می‌رود. مسیرهای مستقیم قدیمی ابزارها حفظ شده‌اند.
- `home_page.dart`، `category_page.dart`، `category_grid.dart` و `tool_tile.dart`: نمایش واکنش‌گرا/RTL، شمارنده‌ها و empty-stateها؛ جستجو در Domain است، نه widget.
- `calculator_page.dart`: فقط callback اختیاری ستاره/ثبت و محدودکردن عنوان نوار بالا برای عرض کم؛ فرم، runner و موتورهای قبلی حفظ شده‌اند. تغییر ستاره ورودی در حال ویرایش را reset نمی‌کند.
- `features/calculators/calculators.dart`: API عمومی مدل‌ها و formatter خلاصهٔ نتیجه برای صفحهٔ خانه.
- `test/features/home/`: ۲۶ تست جستجو/کاتالوگ/فاصله، ۲ تست state، ۱۱ تست widget و یک capture اختیاری.
- `tool/benchmark_catalog_search.dart`: سنجش قابل تکرار روی کاتالوگ واقعی و نمونهٔ مصنوعی جدا.

فهرست دقیق فایل‌های افزوده/ویرایش/حذف نسبت به ZIP مرحلهٔ ۷: `validation/stage08/changed-files.txt`. فقط دو `.gitkeep` خالی منسوخ حذف شده‌اند؛ هیچ موتور، فایل منبع اجرایی یا قابلیت قبلی حذف نشده است. dependency و lockfile تغییر نکرده‌اند.

## تست و شواهد اجرا

محیط: Flutter 3.47.7 stable، Dart 3.13.5، Linux x64 sandbox.

- `flutter analyze`: بدون issue.
- `flutter test --coverage`: **۲۱۹ موفق**، **۸ capture opt-in عمداً skip**؛ شامل **۳۹ تست جدید غیرتصویری**.
- capture جداگانهٔ این مرحله: **۱ موفق** و چهار PNG در `visual/stage08/`.
- فونت‌ها از asset محلی بارگذاری شده‌اند؛ تصاویر رندر widget هستند، نه screenshot سیستم‌عامل یا golden comparison.
- بنچمارک به صورت executable مستقل AOT اجرا شده؛ این اجرا استقلال جستجو/کاتالوگ از Flutter runtime را هم بررسی می‌کند.
- smoke قبلی Domain و سه موتور با Dart مستقل، قالب‌بندی و enforce-lockfile دوباره موفق بوده‌اند.
- تست قدیمی معماری فقط انتظار متن placeholder خانه را به عنوان خانهٔ جدید تغییر داده است؛ بقیهٔ regressionها باقی‌اند.

تست‌های جدید شامل هشت دستهٔ واقعی/خالی، جلوگیری از شناسهٔ تکراری و دستهٔ ناسازگار، immutable بودن فهرست‌ها، حالت‌های نرمال‌سازی، نام/مترادف/توضیح و انگلیسی، رتبه‌بندی/limit، fuzzy و نبود نتیجه است. فاصلهٔ bounded برای **۴۸۰۰ ترکیب رشته/بودجه** با مرجع کامل ماتریسی مقایسه شده است. state برای سقف ده رکورد و تازگی session آزموده شده است. widgetها مسیر دسته‌ها، جستجوی زنده و برچسب fuzzy، حفظ query در بازگشت، حفظ ورودی هنگام تغییر ستاره، غیرفعال‌بودن ثبت نامعتبر، بازگشایی snapshot و آرگومان مسیر اشتباه را می‌آزمایند. چیدمان واقعی خانه و NPV در اندازه‌های ۳۲۰×۵۶۸ و ۱۲۸۰×۸۰۰، هر دو تم و مقیاس متن ۱٫۵، بدون exception/overflow تست شده است.

### سنجش سرعت: دادهٔ واقعی را با دادهٔ آزمایشی مخلوط نکنید

۱۰۰ جستجو warm-up؛ ده پرس‌وجوی چرخشی شامل نام دقیق، عربی/نیم‌فاصله، fuzzy و no-match. هر فراخوانی جدا با Stopwatch اندازه‌گیری، خروجی آن مصرف و نمونه‌ها مرتب شده‌اند. این‌ها اندازه‌گیری همین اجرای sandbox هستند، نه هدف قراردادی و نه تضمین دستگاه.

| کاتالوگ | تعداد ابزار | جستجوی اندازه‌گیری‌شده | ساخت نمایه | میانهٔ هر جستجو | صدک ۹۵ | بیشینه |
|---|---:|---:|---:|---:|---:|---:|
| واقعی برنامه | ۳ | ۳۰۰۰ | ۰٫۶۹۳ ms | ۰٫۰۱۹۰۹۲ ms | ۰٫۰۳۶۳۳۸ ms | ۰٫۷۶۸۴۵۹ ms |
| ساختگیِ آزمون فشار، خارج از برنامه | ۱۰۰۰ | ۳۰۰ | ۱۵۲٫۳۲۴ ms | ۶٫۲۰۶۹۳۵ ms | ۱۱٫۰۵۲۵۱۸ ms | ۱۷٫۷۲۸۱۷ ms |

دادهٔ ساختگی نام و شناسهٔ آزمایشی دارد و توضیح/alias سه ابزار واقعی را تکرار می‌کند؛ شبیه‌ساز همهٔ توزیع‌های دادهٔ آینده نیست. ساخت نمایه جدا از زمان query اندازه‌گیری شده است. این بنچمارک **فقط جستجو** را می‌سنجد، نه زمان تایپ تا رسم فریم، عملکرد IME، کارایی startup یا مصرف باتری. چون کاتالوگ واقعی کوچک است، برای این مرحله dependency، isolate یا debounce اضافی وارد نشده است. پیش از انتشار باید روی Android/Windows واقعی دوباره سنجیده شود.

## بازتولید

از ریشهٔ پروژه با Flutter stable متناظر:

```sh
flutter pub get --enforce-lockfile
flutter analyze
flutter test --coverage
flutter test test/features/home
flutter test --dart-define=CAPTURE_HOME_VISUALS=true test/features/home/home_visual_test.dart
dart run tool/verify_calculator_domain.dart
dart run tool/verify_prototype_engines.dart
dart format --output=none --set-exit-if-changed lib test tool/benchmark_catalog_search.dart

# مثال Linux؛ باینری/خروجی جدید را داخل سورس commit نکنید.
dart compile exe tool/benchmark_catalog_search.dart -o /tmp/catalog_search_benchmark
/tmp/catalog_search_benchmark
```

اجرای `dart run tool/benchmark_catalog_search.dart` هم ممکن است، ولی زمان JIT آن با گزارش AOT این مرحله قابل مقایسهٔ مستقیم نیست. لاگ‌ها و coverage-summary در `validation/stage08/` نگهداری شده‌اند.

## محدودیت‌های تحویل

ذخیرهٔ دائمی و ابزارهای دسته‌های خالی هنوز انجام نشده‌اند. ساخت/نصب APK/AAB، Windows EXE/installer، آزمایش دستگاه/IME/DPI و انتشار GitHub در این مرحله اجرا نشده‌اند؛ Android SDK و میزبان Windows این محیط موجود نیستند. ZIP خروجی، **سورس کامل ادامهٔ همین پروژه** است و فایل نصب یا انتشار عمومی نیست. هیچ token، کلید امضا یا credential اضافه نشده است.
