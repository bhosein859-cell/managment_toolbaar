# مرحلهٔ ۱۷ — واژه‌نامه، ابزارهای عمومی و خروجی متنی

این مرحله روی همان سورس تحویل‌شدهٔ مرحلهٔ ۱۶ ادامه یافته است؛ بازسازی پروژه یا تغییر schema دیتابیس انجام نشده است. ۶۸ ابزار قبلی با همان موتورهای محاسباتی، شناسه‌ها، فونت، لوگو و داده‌های ذخیره‌سازی حفظ شده‌اند. اکنون **۷۳ ابزار در ۹ دسته** داریم.

## قابلیت‌های تحویل‌شده

### واژه‌نامهٔ کاملاً آفلاین

- ورود از آیکون کتاب «واژه‌نامهٔ آفلاین» در نوار بالای خانه؛ مسیر `/glossary`.
- **۷۳ اصطلاح** از `relatedTerms` واقعی ابزارهای نصب‌شده: فارسی، انگلیسی، توضیح کوتاه، توضیح کاملِ قابل بازکردن در موارد بلند، دسته و دکمه‌های ورود به محاسبه‌گر مرتبط.
- جست‌وجوی فارسی/انگلیسی بدون شبکه؛ یکسان‌سازی حروف عربی/فارسی، نیم‌فاصله، اعراب، بزرگی/کوچکی انگلیسی و رقم‌ها از `SearchText` موجود استفاده می‌کند. جست‌وجو روی نام‌ها، توضیح و دسته است؛ ترجمه/آوانویسی خودکار یا جست‌وجوی اینترنتی ندارد.
- فیلتر دسته همراه جست‌وجو اعمال می‌شود؛ حالت بدون نتیجه مشخص است.
- هویت اصطلاح `category:termId` است. تکرار در یک دسته پیوندهای ابزارها را ادغام می‌کند؛ هم‌نامی در دو حوزه بی‌دلیل ادغام نمی‌شود. داده و فهرست پیوندها immutable هستند.
- توضیح کوتاه گزیده‌ای در مرز جمله/بند است؛ متن کامل موجود حذف نمی‌شود. این مرحله ادعای افزودن دانشنامهٔ جامع یا تعاریف تأییدشدهٔ بیرونی ندارد.

### چهار ابزار درصد

همگی در دستهٔ جدید **ابزارهای عمومی**، جست‌وجوی اصلی، علاقه‌مندی‌ها و تاریخچهٔ واقعی در دسترس‌اند و از فرم عمومی موجود استفاده می‌کنند. فرمول‌ها فقط نمایشی‌اند؛ هیچ رشته‌ای به عنوان کد اجرا نمی‌شود.

| شناسهٔ پایدار | کاربرد | مثال | قواعد مهم |
|---|---|---|---|
| `percentage_of` | درصدی از مقدار | ۲۰٪ از ۲۵۰ = ۵۰ | مقدار و درصد نامنفی؛ درصد بیش از ۱۰۰ مجاز |
| `percentage_change` | درصد تغییر | ۱۰۰ به ۱۲۵ = ۲۵٪ | مقدار قبلی اکیداً مثبت و جدید نامنفی؛ مبنای صفر/منفی رد می‌شود؛ کاهش علامت منفی دارد |
| `percentage_base` | مقدار پایه از درصد | ۵۰ معادل ۲۰٪ → پایه ۲۵۰ | بخش نامنفی؛ درصد اکیداً مثبت؛ صفر درصد پاسخ یکتا نمی‌دهد |
| `discount` | تخفیف | ۱۰۰٬۰۰۰ ریال، ۲۰٪ → ۸۰٬۰۰۰ ریال؛ صرفه‌جویی ۲۰٬۰۰۰ | قیمت نامنفی؛ تخفیف ۰ تا ۱۰۰٪؛ یک تخفیف، بدون مالیات/کارمزد |

در فرم، «۲۰» یعنی ۲۰٪؛ در قرارداد Domain درصد به صورت کسر `0.2` است و دوباره تقسیم نمی‌شود. اولین سه ابزار واحد مشترکِ مقدارهای واردشده را حفظ می‌کنند و تبدیل ارز/واحد انجام نمی‌دهند؛ ابزار تخفیف صریحاً **ریال** است. NaN، Infinity، خروج از دامنه و overflow/underflow مؤثر با خطا پاسخ داده می‌شوند، نه نتیجهٔ ساختگی.

### تبدیل واحد — `unit_conversion`

فهرست کامل در توضیح صفحه، راهنمای ورودی و گزینه‌های مبدا/مقصد نمایش داده می‌شود. **۴۲ واحد در ۱۰ گروه** پشتیبانی می‌شود:

| گروه | واحدهای دقیقاً پشتیبانی‌شده |
|---|---|
| طول | میلی‌متر `mm`، سانتی‌متر `cm`، متر `m`، کیلومتر `km`، اینچ بین‌المللی `in`، فوت بین‌المللی `ft`، یارد بین‌المللی `yd` |
| مساحت | `cm²`، `m²`، هکتار `ha`، `km²` |
| حجم | میلی‌لیتر `mL`، لیتر `L`، متر مکعب `m³` |
| جرم | میلی‌گرم `mg`، گرم `g`، کیلوگرم `kg`، تن متریک `t`، پوند جرمی بین‌المللی `lb` |
| زمان | ثانیه `s`، دقیقه `min`، ساعت `h`، روز ۲۴ساعته `d` |
| سرعت | `m/s`، `km/h`، `ft/s` |
| فشار مطلق | پاسکال `Pa`، `kPa`، `MPa`، بار `bar`، `psi` |
| انرژی | ژول `J`، `kJ`، `MJ`، وات‌ساعت `Wh`، کیلووات‌ساعت `kWh` |
| توان | وات `W`، `kW`، `MW` |
| دمای مطلق | سلسیوس `°C`، فارنهایت `°F`، کلوین `K` |

- تبدیل فقط بین واحدهای هم‌بعد است؛ انتخاب مثلاً متر به کیلوگرم خطای روشن در فیلد مقصد می‌دهد. رابط هر دو فهرست را نشان می‌دهد و ناسازگاری را پنهان یا خودکار اصلاح نمی‌کند.
- کمیت‌ها قدر مطلق و نامنفی‌اند؛ استثنا دمای سلسیوس/فارنهایت تا صفر مطلق است. حدها: `−273.15 °C`، `−459.67 °F` و `0 K`. دمای اختلافی و فشار گیج پشتیبانی نمی‌شوند.
- ماه/سال تقویمی، گالن و تن مبهم، اسب‌بخار، تبدیل جرم/نیرو و ارز وجود ندارند. هیچ واحدی بدون اعلام به فهرست اضافه نشده است.
- ضریب‌ها ثابت‌اند؛ مثلاً اینچ دقیقاً ۰٫۰۲۵۴ متر، پوند جرمی ۰٫۴۵۳۵۹۲۳۷ کیلوگرم، روز ۸۶۴۰۰ ثانیه، kWh برابر ۳۶۰۰۰۰۰ ژول است. psi از پوندنیرو استاندارد ۴٫۴۴۸۲۲۱۶۱۵۲۶۰۵ نیوتن و اینچ مربع به دست می‌آید.
- پیاده‌سازی با double است، نه حساب نمادین با دقت نامحدود. تبدیل دما در نزدیکی صفر مطلق و نقطهٔ انجماد مبدا مناسب دارد؛ ۳۲°F به ۰°C دقیقاً صفر برمی‌گردد. هم‌واحد بودن مقدار را بی‌دلیل سرریز نمی‌کند. خروجی غیرمتناهی/صفر ناشی از underflow کمیت مثبت رد می‌شود.

## کپی و اشتراک نتیجه

در کارت نتیجهٔ **تمام ۷۳ ابزار**، «کپی سریع» و «اشتراک متنی» اضافه شده است؛ نتیجهٔ نامعتبر خروجی قابل ارسال ندارد.

- متن شامل برند، نام فارسی/انگلیسی ابزار، ورودی‌های خام با واحد/درصد، نام گزینهٔ انتخابی، سطرهای سری عددی، نتیجهٔ اصلی، جزئیات، هشدارها/فرض‌ها و نام سازنده است.
- نتیجه با همان قالب نمایش UI (تا ۶ رقم اعشار و نمایش علمی برای مقیاس‌های خیلی کوچک/بزرگ) صادر می‌شود؛ فایل تبادل بدون اتلاف دقت نیست. متن خام ورودی‌ها دست‌نخورده حفظ می‌شود؛ انتخاب واحد با نام خوانا نمایش داده می‌شود.
- ورودی و نتیجهٔ زنده در **لحظهٔ فشار دکمه** با هم snapshot می‌شوند؛ حتی پیش از فریم بعدی، نتیجهٔ قدیمی با ورودی جدید جفت نمی‌شود. هنگام انجام عملیات، ارسال تکراری مسدود است.
- Clipboard واقعی از Flutter و اشتراک از `share_plus 13.3.1` استفاده می‌کند؛ dependency صرفاً نمایشی نیست. سرویس قابل تزریق برای تست مستقل وجود دارد.
- لغو اشتراک، وضعیت غیرقابل گزارش و استثنا پیام‌های جدا دارند. تحویل به رابط سیستم به معنی دریافت/خواندن توسط مخاطب اعلام نمی‌شود.
- محاسبات/واژه‌نامه آفلاین‌اند؛ ارسال به اپ مقصد فقط با اقدام خود کاربر است و اپ مقصد ممکن است شبکه بخواهد. هیچ ارسال خودکار، sync، backend یا سرویس تحلیلی افزوده نشده است. متن کپی‌شده می‌تواند اطلاعات ورودی کاربر را داشته باشد.

### سازگاری اشتراک بومی

- Flutter **3.47.7 stable** و Dart **3.13.5**؛ حل dependencyها و analyzer موفق.
- بسته نیازمند Flutter حداقل 3.38.1، Dart حداقل 3.10، Java 17، Kotlin 2.2، AGP حداقل 8.12.1 و Gradle حداقل 8.13 است. تنظیمات پروژه Java 17، AGP 9.1.0، Kotlin 2.4.0 و Gradle 9.3.1 هستند. سورس Android بسته شاخهٔ سازگاری AGP 9 و minSdk 21 دارد؛ minSdk پروژه همچنان **26** است.
- Windows: ثبت‌کننده‌های تولیدشدهٔ `share_plus` و `url_launcher_windows` در سورس هستند. پیاده‌سازی جدید ویندوز از Share UI استفاده می‌کند؛ در Windows 10 قدیمی‌تر از RS5/build 17763 مسیر متن می‌تواند `mailto` باشد و به برنامهٔ ایمیل/ثبت handler وابسته است. Windows 10/11 را یکسان با Android توصیف نمی‌کنیم.
- تست channel، متن و نگاشت success/dismissed/unavailable را بررسی کرده است؛ **APK/EXE جدید، ساخت بومی Android/Windows و آزمون واقعی Share Sheet روی دستگاه در این محیط انجام نشده‌اند**. این موارد هنوز باید روی میزبان‌های هدف بررسی شوند؛ خطا به کاربر گزارش می‌شود و کپی در دسترس است.

## تصمیم PDF: غیرفعال، با شاهد واقعی

`pdf 3.13.1` فقط **dev_dependency** برای آزمون سازگاری/رندر است. هیچ import از pdf در `lib/` و هیچ مسیر ساخت یا اشتراک PDF در اپ فعال نیست. کارت نتیجه علت غیرفعال بودن را هم در متن و هم tooltip نشان می‌دهد و دکمه handler ندارد.

آزمون واقعی با لوگوی محلی، Vazirmatn Regular/Bold و متن‌های شامل پ/چ/ژ/گ، نیم‌فاصله، NPV/OEE/ROI، اعداد فارسی/انگلیسی، درصد، منفی، واحد دما و چند صفحه اجرا شد:

1. تولید یک PDF چهارصفحه‌ای با نسخهٔ pinned روی Dart 3.13.5 موفق بود؛ بنابراین ناسازگاری resolver ادعا نمی‌شود.
2. هر چهار صفحه با **PyMuPDF 1.28.2** rasterize شد و تصویر صفحهٔ اول بررسی شد.
3. بیشتر اتصال حروف فارسی قابل قبول بود، اما واحد `°F`/`°C` به `F°`/`C°` تغییر ترتیب می‌داد، پرانتزهای ROI و بخش‌های متن ترکیبی/علامت درصد و منفی قابل اتکا نبودند. صرف نمایش حروف فارسی معیار قبولی نیست.
4. استخراج ترتیب هندسی glyphها نیز معکوس شدن واحد دما را تأیید می‌کند. Gate متن ترکیبی **FAIL** است؛ در نتیجه طبق شرط درخواست PDF فعال نشده است.

شواهد در `docs/validation/stage17/pdf/`: ورودی منطقی، `persian-probe.pdf`، تصاویر `page-1.png` تا `page-4.png` و `render-report.json`. PDF نمونه، خروجی آزمایش معیوب است، نه قابلیت آمادهٔ انتشار. این محدودیت مربوط به این مسیر رندر/نسخه/تنظیمات آزمایش‌شده است، نه ادعای ناممکن بودن PDF فارسی در همهٔ کتابخانه‌ها. فعال‌سازی آینده به رندر اصلاح‌شده، بازبینی مجدد متن ترکیبی و آزمون بومی خروجی نیاز دارد.

بازتولید:

```sh
dart run tool/probe_persian_pdf.dart
# Python فقط ابزار توسعه است، نه وابستگی اپ
python -m pip install PyMuPDF==1.28.2
python tool/render_pdf_probe.py
```

خروج صفر اسکریپت Python یعنی شاهد شکست مورد انتظار ثبت شد؛ به معنی قبولی PDF نیست. اگر مشکل دیگر بازتولید نشود اسکریپت متوقف می‌شود و بازبینی انسانی لازم است.

## نگهداری داده و معماری

- پنج موتور و پارامترهای typed مستقل در `features/utilities/domain`؛ رجیستری واحدها و منطق محاسبه بدون Flutter.
- metadata و runnerها در `app/catalog/utility_calculators.dart`؛ اتصال دسته، جست‌وجو، مسیر و شمارنده‌ها در ساختار موجود.
- واژه‌نامه Domain/UI جدا؛ قالب خروجی و آداپتور Clipboard/Share از منطق محاسبه جدا هستند.
- schema **2** و payload **1**، ذخیرهٔ صریح دستی و محدودیت اتمیک آخرین ۱۰ ثبت بدون تغییر حفظ شده‌اند. تست ذخیرهٔ هر پنج ابزار در فایل SQLite، بستن/بازکردن و بازاجرای ورودی خام موفق است. هیچ migration اضافه، پاک‌کردن داده یا fallback حافظه‌ای پنهان نداریم.
- مقایسه با ZIP مرحلهٔ ۱۶: موتورهای قبلی، سورس storage/history data، لوگو و فونت‌ها byte-identical هستند. تنها تغییر قرارداد قدیمی Domain، افزودن مقدار انتهایی `utilities` به enum دسته‌هاست.
- فهرست دقیق فایل‌های افزوده/تغییریافته: `docs/validation/stage17/changed-files.txt`.

## اعتبارسنجی اجراشده

| بررسی | نتیجهٔ همین مرحله |
|---|---|
| `flutter pub get` | موفق، نسخه‌ها pinned و lockfile به‌روز |
| `flutter analyze` | بدون issue |
| کل مجموعه، ۸۲ فایل، ۲۱ دستهٔ جدا | **۱۶۷۹ موفق + ۱۳ skip اختیاریِ تصاویر قدیمی؛ صفر شکست** |
| آزمون‌های متمرکز واژه‌نامه/ابزارها/خروجی/ذخیره‌سازی | **۳۴۷ موفق** |
| پوشش خطی محدود به Domain جدید، واژه‌نامه، قالب خروجی و آداپتورها | **۳۵۵/۳۵۶ = ۹۹٫۷۲٪**؛ پوشش خط، نه پوشش branch یا کل اپ |
| smokeهای مستقل Dart | ۹ smoke قدیمی و یک smoke جدید موفق؛ ۷۳ اصطلاح و ۴۲ واحد تأیید شد |
| آزمون PDF | تولید/رندر موفق، معیار صحت متن ترکیبی شکست؛ قابلیت غیرفعال |

تست‌ها شامل مرجع مستقل رفت/برگشت برای همهٔ ۴۲ واحد، تمام جفت‌های هم‌بعد، صفر مطلق، دمای منفی معتبر، ناهم‌بعدی، NaN/Infinity، overflow/underflow، قواعد چهار ابزار درصد، ورودی فارسی/عربی، مثال‌ها، خروجی واقعی همهٔ ۷۳ ابزار، کپی/اشتراک و خطا/لغو، snapshot لحظهٔ tap، رابط ۳۲۰/۱۲۸۰ روشن/تیره، جست‌وجو و فیلتر واژه‌نامه و مسیر واقعی خانه→واژه‌نامه→محاسبه‌گر→ثبت/علاقه‌مندی هستند. پنج round-trip جدید codec نیز در مجموعهٔ کامل اجرا شده‌اند.

در این محیط ۲GB، اجرای اولیهٔ یک‌جای تست‌ها و اولین تلاش دسته‌بندی با scratch باقی‌مانده در `/tmp`ِ RAM-backed به محدودیت حافظه برخورد کرد. آن اجراها قبولی اعلام نشده‌اند. scratch دورریختنی پاک شد و اجرای نهایی با فضای موقت روی دیسک و دسته‌های جدا، **تمام ۸۲ فایل بدون حذف تست** را با موفقیت پوشش داد. شمارش نهایی و لیست همهٔ فایل‌ها در `shards/summary.json` است. اسکریپت جدید در نبود TMPDIR، فضای دیسکی `.dart_tool/test-shard-tmp` را انتخاب می‌کند.

```sh
flutter pub get
flutter analyze
# میزبان معمولی با حافظهٔ کافی:
flutter test
# جایگزین کامل برای میزبان کم‌حافظه؛ هیچ تستی حذف نمی‌شود:
python tool/run_test_shards.py --flutter /path/to/flutter --batch-size 4
# قابلیت‌های این مرحله:
flutter test test/features/utilities test/features/glossary --concurrency=1 --coverage
dart run tool/verify_utilities.dart
dart format --output=none --set-exit-if-changed lib test tool
```

لاگ‌های نهایی در `docs/validation/stage17/` هستند. روی GitHub push/commit یا انتشار انجام نشده و کلید/توکن/signing material در بسته نیست. برای Android و Windows همان سورس فعلی را روی میزبان مربوط بسازید؛ این تحویل سورس است، نه APK یا EXE آزمایش‌شده.
